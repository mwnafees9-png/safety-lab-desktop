FMEA

FMEA that is wired into the fault tree

Functional and piece-part FMEA that feeds your quantification instead of living in a disconnected spreadsheet.

Fault Tree AnalysisCommon-cause analysisARP 4761A

FMEA is your bottom-up evidence — the systematic walk through how components and functions fail and what those failures do. Its value multiplies when it connects to the top-down fault tree analysis above it, which is exactly where most toolchains break the link. Safety Lab Aero keeps them connected.

Functional FMEA

Each row links to an aircraft sub-function and records the function failure mode — loss, erroneous, inadvertent, degraded — and its effects. Optionally link the row to the FHA failure condition it contributes to, closing the loop from functional FMEA back to the hazard assessment.

Piece-part (hardware) FMEA

  • Each row links to a fault-tree basic event and records a component failure mode with its failure-mode fraction and rate.
  • A component basic event takes the sum of its failure-mode rates, so multiple modes aggregate correctly rather than overwriting one another.
  • Optionally choose a parent library component; the mode rate is computed from the component rate and the failure-mode fraction, and the published mode menu pre-fills the fractions.
  • A coverage check warns when the failure-mode fractions for a basic event do not sum to one — i.e. part of the component failure rate is unmodeled.

One source of truth for failure data

The component library catalogs failure rates from public-domain sources (MIL-HDBK-217F, MIL-HDBK-338B, NPRD/EPRD-style data, NUREG-CR-6928 and others), with environment, quality and temperature factors. When several basic events reference the same library entry, Safety Lab Aero flags the shared dependency so you can decide whether it needs common-cause treatment — see CMA, PRA and ZSA.

Frequently asked questions

Does the FMEA connect to the fault tree?

Yes. Piece-part FMEA rows link to fault-tree basic events and supply their rates, and functional FMEA rows can link to the FHA failure condition they contribute to. The FMEA is part of the same model, not a separate file.

How does it handle a component with several failure modes?

The basic event takes the sum of its failure-mode rates, and a coverage check warns if the failure-mode fractions do not sum to one, so unmodeled portions of the component rate are visible rather than hidden.
